Deployment order

Seven stacks, applied in this order. Click one to see what it builds.

No stored secrets in CI

The pipeline signs in with a federated identity credential. The workflows request id-token: write and call azure/login@v2 with OIDC, so there is no client secret to leak or rotate. The plan job runs on pull requests, and apply is serialized behind a production environment gate.

1

PR opens

The plan workflow authenticates with a credential scoped to pull requests, runs a plan per workspace and posts the diff.

2

Review

The plan diff is in the pull request for people to read.

3

Merge and approve

Apply uses a credential scoped to the main branch and waits for the production environment approval.

Use it

Terraform 1.7 or later and an Azure tenant. Every company-specific value in the repo is a PLACEHOLDER_*.

az ad app create --display-name "PLACEHOLDER_SP_NAME"
az ad sp create --id <app-id>
# add federated credentials for main and pull_request,
# then set AZURE_CLIENT_ID and AZURE_TENANT_ID as repo secrets
cd platform/hub-network
terraform init
terraform plan

The stacks call versioned modules from terraform-infra-blueprints.

What this does not do
